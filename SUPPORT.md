# Support

## Where to ask

Open a GitHub issue in the repository that owns the problem:

| Problem | Repository |
|---|---|
| API, workers, graph backends, auth, deployment | [openzync-core](https://github.com/openzync/openzync-core/issues) |
| Python client, LangChain integrations | [openzync-python-sdk](https://github.com/openzync/openzync-python-sdk/issues) |
| MCP server tools and transport | [openzync-mcp](https://github.com/openzync/openzync-mcp/issues) |
| Dashboard behavior and UI | [openzync-frontend](https://github.com/openzync/openzync-frontend/issues) |
| Documentation gaps and errors | [openzync-docs](https://github.com/openzync/openzync-docs/issues) |
| Marketing site and blog | [openzync-landing](https://github.com/openzync/openzync-landing/issues) |

Security vulnerabilities do not go in an issue. Report them by email as described in
[SECURITY.md](./SECURITY.md).

## Before you open an issue

- Read the [documentation](https://docs.openzync.tech/en/latest/), particularly the
  [quickstart](https://docs.openzync.tech/en/latest/guides/quickstart.html) and
  [deployment](https://docs.openzync.tech/en/latest/guides/deployment.html) guides.
- Search existing issues and closed pull requests for the same error.
- Include your version (commit, image tag, or PyPI version), how you deployed it, and the relevant
  logs with API keys and personal data removed.

## In scope

Best-effort help from maintainers with the code in the [openzync](https://github.com/openzync)
organization: setup failures, upgrade problems, incorrect behavior, and documentation errors.
Bug reports with a reproduction get attention first.

## Out of scope

- No SLA, no guaranteed response time, and no paid support tier.
- No private consulting, no debugging of your application code, and no managed hosting.
- No support for modified forks beyond pointing at the upstream fix.
